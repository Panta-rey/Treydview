TreydView ist eine "Zero-Build Vanilla JS Single Page Application" — gehostet als statische Site auf GitHub Pages.

Architektur-Charakteristik:

-Kein Build-Step, kein Bundler (kein Webpack, Vite, Rollup), kein Transpiler (kein Babel/TypeScript)
-Kein Framework (kein React, Vue, Angular) — reines Vanilla JavaScript
Modulisolation via IIFE-Pattern (Immediately Invoked Function Expressions) statt ES-Modules
-Browser-native APIs ausschliesslich: fetch, WebSocket, Canvas, localStorage, requestAnimationFrame
-Einziges Backend: ein Cloudflare Worker für Golddaten — alles andere direkt Browser→Exchange-API (CORS-abhängig)
-Persistenz nur via localStorage — keine Datenbank, kein Server
-Layered Canvas-Architektur: eigene Canvas-Ebenen über einer gepatchten Drittanbieter-Charting-Engine (KLineCharts, manuell im Minified-Bundle gepatcht)

Wenn du das Expertenteam briefst, würde ich sagen:

„Wir haben eine framework-freie, build-step-freie statische Web-App, die ausschliesslich im Browser läuft. Keine Server-Infrastruktur ausser einem Cloudflare Worker. Alle Daten kommen direkt aus öffentlichen Exchange-APIs via Browser-Fetch. Der gesamte State lebt im RAM und localStorage. Deployment ist ein Git-Push auf GitHub Pages."
